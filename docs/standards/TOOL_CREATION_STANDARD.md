# Tool Creation Standard (Reference for Every Tool)

## Mission

Every tool must be designed as if it will become the best result on the
web for its specific search intent.

The objective is **not** to generate content.

The objective is to build a genuinely useful browser based utility that
deserves to rank because it solves the user's problem better than
competing pages.

Quality is more important than quantity.

------------------------------------------------------------------------

# Product First

The tool is the product.

The article exists to explain, teach, and support the tool.

Never create filler content simply to reach a word count.

Every tool should feel handcrafted.

The page must never resemble a generic AI content farm.

------------------------------------------------------------------------

# Tool Requirements

Every tool must:

-   Work entirely in the browser whenever possible.
-   Be fast.
-   Be mobile friendly.
-   Produce accurate outputs.
-   Include input validation.
-   Handle edge cases.
-   Display useful error states.
-   Explain formulas when applicable.
-   Allow copying results.
-   Allow downloading results when appropriate.
-   Include one meaningful differentiator such as:
    -   visual charts
    -   presets
    -   comparison mode
    -   export options
    -   history
    -   advanced mode
    -   formula breakdown
    -   live calculations

------------------------------------------------------------------------

# Keyword Research

Before building anything identify:

-   Primary keyword
-   5--8 long tail keywords
-   Question keywords
-   Comparison keywords
-   Alternative terminology
-   Related entities
-   Search intent
-   Competition estimate
-   Why this keyword should rank

Requirements:

-   Low competition
-   High intent
-   No keyword cannibalization
-   One page = one primary intent

------------------------------------------------------------------------

# SEO Structure

The focus keyword must appear naturally in:

-   URL slug
-   H1
-   SEO title
-   Meta description
-   First 10 percent of content
-   Image alt text (when applicable)

Generate:

-   SEO title
-   CTR optimized title
-   Meta description
-   Open Graph title
-   Open Graph description
-   Twitter title
-   Twitter description

------------------------------------------------------------------------

# Content Requirements

Write only enough content to completely satisfy search intent.

Target approximately 700--1400 words only when appropriate.

Never pad content.

Every article should include:

-   Introduction
-   How to use the tool
-   Example
-   Formula or methodology
-   Real world use case
-   Common mistakes
-   Pro tips
-   Limitations
-   Frequently asked questions
-   Summary

Every introduction must be structurally unique.

Never reuse openings or section order.

------------------------------------------------------------------------

# EEAT

Demonstrate trust by:

-   Explaining assumptions
-   Showing formulas
-   Showing limitations
-   Citing authoritative sources
-   Explaining when users should seek professional advice

Use authoritative references only.

------------------------------------------------------------------------

# Internal Linking

Every page must include:

-   Parent category links
-   Sibling tools
-   Related tools
-   Child tools (when applicable)

Create topical clusters.

Never leave a page isolated.

------------------------------------------------------------------------

# External Links

Use 3--5 high quality authoritative references when appropriate.

Prefer government, academic, standards organizations, or highly trusted
industry sources.

------------------------------------------------------------------------

# Structured Data

Generate structured data where applicable:

-   BreadcrumbList
-   WebApplication
-   FAQPage
-   Organization
-   WebSite
-   Article
-   HowTo (if appropriate)

------------------------------------------------------------------------

# Technical SEO

Include:

-   Canonical URL
-   Breadcrumbs
-   Optimized sitemap inclusion
-   Clean semantic HTML
-   Accessible labels
-   Fast rendering
-   Core Web Vitals friendly markup

------------------------------------------------------------------------

# UX

The page should immediately answer:

What is this?

Who is it for?

How do I use it?

Why should I trust it?

What should I do next?

------------------------------------------------------------------------

# Differentiation

Every page must contain something competitors do not.

Never clone another site's structure.

Never copy wording.

Never imitate headings.

Improve upon existing solutions.

------------------------------------------------------------------------

# Brand

Use a reusable platform section near the bottom describing the platform.

Keep wording consistent but rotate phrasing enough to avoid obvious
duplication.

------------------------------------------------------------------------

# Final Quality Checklist

Before completion verify:

-   Tool works correctly
-   Mobile responsive
-   No console errors
-   Primary keyword targeted
-   No duplicate content
-   Helpful article
-   Strong internal links
-   Strong schema
-   Fast page
-   Unique value
-   Solves the user's problem better than competitors

The standard for every page is:

**Build the best browser based utility on the internet for that exact
search intent.**
